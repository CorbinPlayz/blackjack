# Handoff: Blackjack Chip Tracker (friends-only, no real money)

## What it is
A chip tracker for an in-person blackjack game (the cards are physical, only chips live in the app).
- `index.html`: the whole client, one file, vanilla JS. Script 1 = `Core` (offline rules, localStorage). Script 2 = UI IIFE. `<script type="text/plain" id="triviaData">` holds 594 trivia questions (`#Category` lines, then `question|correct|wrong|wrong|wrong`).
- `worker/src/index.js`: Cloudflare Worker `blackjack-table` (Durable Objects `Room` = one table, `Registry` = approved devices/Google accounts + vaults). Secret `ADMIN_KEY` (held by the user, NOT in the repo).
- Hosted on GitHub Pages (from `main`); the worker URL is the `ONLINE_URL` constant in `index.html` (blackjack-table.camc-cf76.workers.dev). Google Client ID is in both files (`GOOGLE_CLIENT_ID`).
- The server is the referee: `applyAction(table, actor, action, ctx)`. The client polls every 1.5s and mostly just renders the snapshot.

## Features already shipped (on main + deployed)
Invite-only access (Google sign-in or name request, admin approves), seats (players only touch their own chips, host/dealer touch all), rounds (wager -> dealer Start -> hands -> next round), double down, dealer hand-over (request/accept/reject/set), trivia (max 20% of buy-in, host-set), bank fee + trip limit, vault (savings per account), insurance, standings/net profit, effects + sound, tab layout (Table / Board / Me / Host / Admin) with bottom nav.

Seat balance cash-out must be credited exactly once (server-authoritative, idempotent, e.g. on remove/leave/table end).

ANTI-CHEAT REQUIREMENTS (user concern 2026-11-14: "create a lobby and double, double, double..."): today a player may `settle` their OWN hand (`may(p)` = dealerPower || mine(p)) and the host can `add` players/chips from nothing; both must be closed in the bank version. Rules: (1) real money only moves through account-backed seats: host `add` with free chips is removed; every seat is funded from an account. (2) A player can NEVER settle their own win: results need the dealer to enter them AND the player to confirm (or the dealer is a different account than the winner, and a host who is also the sole player earns nothing from the casino). (3) Wins are paid from the casino pot / other players' stakes, never created, so doubling only raises risk, and a self-run lobby with colluding friends cannot print money; it can only drain the pot, so add: max bet per hand (e.g. 5% of pot or 10% of the bettor's net worth), max casino payout per account per day, and a max win streak/size flag. (4) Doubling already needs chips (hand*2 <= balance); keep. (5) Every settle goes in the ledger with who entered it; admin screen shows suspicious accounts (big wins, only playing with one friend, lobbies with <3 players). (6) Casino payouts only from tables with at least 2 real players besides the dealer, or else the table is "friendly" (no casino money at all, only player-to-player). Test: randomized collusion simulation (2 colluding accounts, host settles) must leave total money conserved and per-day casino drain under the cap.
ONLINE DEALER (user idea 2026-11-14): to keep play quick and kill self-settle cheating, add an automatic server-side dealer. Server shuffles a ~6-deck shoe, deals, runs the dealer (hits to 17, BJ 3:2), settles into accounts and ledger automatically; no human settles. Hidden hole card and shoe never sent to clients until revealed. Round flow: auto-repeat bets -> deal -> all players act simultaneously (Hit/Stand/Double/Split once/Insurance) with ~15s auto-stand timer -> dealer plays out -> results -> next round automatically. Two table kinds: ONLINE DEALER table (only kind that can pay from the casino pot) and IN-PERSON chip tracker (today's behaviour, friendly/no casino money or reduced limits). Optional "basic strategy" button. Suggested defaults (unconfirmed): split once, 6 decks, dealer stands on all 17s. Build order: accounts+ledger+grant -> online dealer table -> account-backed buy-in/cash-out -> casino pot/dealer cut -> lockdown -> leaderboard -> loans. Unit-test the engine (shuffle uses crypto.getRandomValues, hand totals, soft aces, splits, doubles, payouts) and the money-conservation invariant.
